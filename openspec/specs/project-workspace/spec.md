# project-workspace Specification

## Purpose

管理 UML 專案檔的生命週期（新建、開啟、儲存）與工作區導覽（模型樹、圖分頁），讓一份共用模型能在多張圖之間長期維護。

## Requirements

### Requirement: 新建專案
系統 SHALL 允許使用者建立一個空白專案，內含空的模型與零張圖。

#### Scenario: 建立空白專案
- **WHEN** 使用者選擇「新專案」
- **THEN** 工作區顯示空的模型樹與無任何圖分頁，且專案標記為未儲存

### Requirement: 儲存專案到本機檔案
系統 SHALL 將整個專案（模型與所有圖）序列化為單一 JSON 檔並寫入使用者選擇的本機位置；已有檔案時，後續儲存 SHALL 直接覆寫同一檔案。

#### Scenario: 首次儲存
- **WHEN** 使用者對未曾儲存的專案選擇「儲存」
- **THEN** 系統要求選擇檔案位置，寫入後清除未儲存標記

#### Scenario: 再次儲存
- **WHEN** 已開啟自某檔案的專案有變更且使用者選擇「儲存」
- **THEN** 系統直接覆寫該檔案，不再詢問位置

#### Scenario: 儲存失敗
- **WHEN** 寫入檔案失敗（例如權限被拒）
- **THEN** 系統顯示錯誤訊息，且未儲存標記保持不變

### Requirement: 開啟專案檔
系統 SHALL 從本機讀取專案 JSON 檔並載入為目前專案。

#### Scenario: 成功開啟
- **WHEN** 使用者選擇一個有效的專案檔
- **THEN** 模型樹與圖分頁顯示該檔案內容

#### Scenario: 檔案格式錯誤
- **WHEN** 檔案不是有效 JSON，或格式版本不受支援
- **THEN** 系統顯示錯誤訊息，目前已開啟的專案保持不變

#### Scenario: 圖參照不存在的模型元素
- **WHEN** 檔案中某張圖引用了模型中不存在的元素或關係
- **THEN** 系統略過該圖形項目並照常開啟其餘內容

### Requirement: 存檔往返一致
儲存後再開啟的專案 SHALL 與儲存前的模型與圖內容完全相同。

#### Scenario: 往返
- **WHEN** 使用者儲存專案後重新開啟該檔案
- **THEN** 所有元素、關係、圖、位置與訊息順序皆與儲存前相同

### Requirement: 不支援檔案系統 API 時的退回
在不支援直接讀寫本機檔案的瀏覽器中，系統 SHALL 以下載檔案方式儲存、以檔案選擇器方式開啟。

#### Scenario: 退回下載
- **WHEN** 瀏覽器不支援直接寫入本機檔案且使用者選擇「儲存」
- **THEN** 系統以下載方式提供專案檔

### Requirement: 模型樹
系統 SHALL 在工作區側邊顯示模型中所有元素，並允許將元素拖曳到目前的類別圖上建立其圖形。

#### Scenario: 拖曳元素到圖上
- **WHEN** 使用者將模型樹中的 Class 拖曳到類別圖畫布
- **THEN** 該 Class 出現在放開的位置，且與既有模型元素為同一個（非複製）

#### Scenario: 從模型樹刪除元素
- **WHEN** 使用者在模型樹刪除一個元素
- **THEN** 該元素、所有相連關係，以及所有圖中對它的圖形與生命線綁定都被移除

### Requirement: 圖分頁管理
系統 SHALL 允許新增（類別圖或循序圖）、重新命名、刪除、切換圖，並以分頁呈現。

#### Scenario: 新增循序圖
- **WHEN** 使用者新增一張循序圖
- **THEN** 出現新的分頁並切換到該空白循序圖

#### Scenario: 刪除圖不影響模型
- **WHEN** 使用者刪除一張類別圖
- **THEN** 圖被移除，但其上顯示過的模型元素仍保留在模型樹

### Requirement: 未儲存變更提醒
專案有未儲存變更時，系統 SHALL 在使用者關閉或重新整理頁面、開新專案或開啟其他檔案前提出確認。

#### Scenario: 關閉頁面前提醒
- **WHEN** 專案有未儲存變更且使用者關閉分頁
- **THEN** 瀏覽器顯示離開確認
