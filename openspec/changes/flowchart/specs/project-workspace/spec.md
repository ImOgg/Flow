# Spec Delta

## MODIFIED Requirements

### Requirement: 開啟專案檔
系統 SHALL 從本機讀取專案 JSON 檔並載入為目前專案。舊版本（版本 1、2）的專案檔 SHALL 自動轉換為目前版本後載入，之後儲存一律寫成目前版本。

#### Scenario: 成功開啟
- **WHEN** 使用者選擇一個有效的專案檔
- **THEN** 模型樹與圖分頁顯示該檔案內容

#### Scenario: 開啟第一期的檔案
- **WHEN** 使用者開啟版本 1 的專案檔
- **THEN** 檔案內容照常顯示，所有圖都沒有 Note 與 Package，連線使用自動路徑；儲存後檔案版本為 3

#### Scenario: 開啟第二期的檔案
- **WHEN** 使用者開啟版本 2 的專案檔
- **THEN** 檔案內容照常顯示；儲存後檔案版本為 3

#### Scenario: 檔案格式錯誤
- **WHEN** 檔案不是有效 JSON，或格式版本不受支援
- **THEN** 系統顯示錯誤訊息，目前已開啟的專案保持不變

#### Scenario: 圖參照不存在的模型元素
- **WHEN** 檔案中某張圖引用了模型中不存在的元素或關係
- **THEN** 系統略過該圖形項目並照常開啟其餘內容

#### Scenario: Note 或 Package 參照不存在的項目
- **WHEN** 檔案中 Note 連結或 Package 成員指向圖上不存在的元素，或循序圖 Note 覆蓋不存在的生命線
- **THEN** 系統略過該連結、成員或生命線並照常開啟；覆蓋的生命線全部不存在的 Note 一併略過

#### Scenario: 流程圖參照不存在的節點
- **WHEN** 檔案中流程圖的箭頭起點或終點、或子圖成員指向該圖不存在的節點
- **THEN** 系統略過該箭頭或成員並照常開啟其餘內容

### Requirement: 存檔往返一致
儲存後再開啟的專案 SHALL 與儲存前的模型與圖內容完全相同。

#### Scenario: 往返
- **WHEN** 使用者儲存專案後重新開啟該檔案
- **THEN** 所有元素、關係、圖、位置、訊息順序、Note、Package 成員與連線轉折點皆與儲存前相同

#### Scenario: 流程圖往返
- **WHEN** 使用者儲存含流程圖的專案後重新開啟
- **THEN** 流程圖的節點形狀、文字、位置、箭頭與標籤、轉折點、子圖與其成員皆與儲存前相同

### Requirement: 圖分頁管理
系統 SHALL 允許新增（類別圖、循序圖或流程圖）、重新命名、刪除、切換圖，並以分頁呈現。

#### Scenario: 新增循序圖
- **WHEN** 使用者新增一張循序圖
- **THEN** 出現新的分頁並切換到該空白循序圖

#### Scenario: 新增流程圖
- **WHEN** 使用者新增一張流程圖
- **THEN** 出現新的分頁並切換到該空白流程圖

#### Scenario: 刪除圖不影響模型
- **WHEN** 使用者刪除一張類別圖
- **THEN** 圖被移除，但其上顯示過的模型元素仍保留在模型樹
