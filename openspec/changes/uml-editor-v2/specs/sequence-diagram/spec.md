# Spec Delta

## ADDED Requirements

### Requirement: 執行區段自動計算
系統 SHALL 依訊息由上而下的順序自動計算每條生命線的執行區段（activation），使用者不需手動建立：收到同步訊息時接收者開始一段執行區段；回傳訊息結束發送者最內層的執行區段；發出同步訊息時若發送者沒有執行區段，則從該訊息開始一段。計算時忽略片段邊界，只看訊息的上下順序。

#### Scenario: 一來一回
- **WHEN** 依序有 `Client -> Service: getUser()` 與 `Service --> Client: user`
- **THEN** Service 的生命線上有一段從第一則訊息到第二則訊息的執行區段，Client 從第一則訊息開始也有一段執行區段

#### Scenario: 巢狀呼叫
- **WHEN** 依序有 `A -> B: f()`、`B -> C: g()`、`C --> B: r1`、`B --> A: r2`
- **THEN** C 的執行區段完整落在 B 的執行區段時間範圍內，B 的執行區段結束在 `r2`

#### Scenario: 沒有回傳
- **WHEN** 收到同步訊息的生命線之後沒有對應的回傳訊息
- **THEN** 該執行區段延伸到這條生命線最後一則相關訊息的下方

#### Scenario: 與回傳不成對
- **WHEN** 一則回傳訊息的發送者當下沒有執行區段
- **THEN** 該訊息照常繪製，不影響任何執行區段

### Requirement: 執行區段繪製
執行區段 SHALL 繪製為疊在生命線虛線上的細長白底矩形；同一生命線上的巢狀執行區段（例如對自己發送的同步訊息）SHALL 往右錯開一格疊放。訊息箭頭 SHALL 連到兩端執行區段的邊緣，而非生命線中心。

#### Scenario: 自呼叫的巢狀區段
- **WHEN** B 在執行區段中發送 `B -> B: validate()`
- **THEN** B 的生命線上出現一段往右錯開的較短執行區段，自迴圈箭頭連到它的邊緣

#### Scenario: 匯出包含執行區段
- **WHEN** 使用者匯出循序圖為 SVG
- **THEN** 圖中包含所有執行區段
